### Fix your .env first

Right now it sets `RMP_BASE_URL`, `RMP_MODEL` and `RMP_API_KEY` **twice** — the
Gemini lines and the Groq lines you pasted underneath. The loader now takes the
last of each and warns you about it, so Groq is live, but `RMP_MODEL` is empty.
**Delete the Gemini lines** and leave exactly this:

```
RMP_PROVIDER=openai_compat
RMP_BASE_URL=groq
RMP_MODEL=openai/gpt-oss-120b
RMP_API_KEY=<your groq key, the gsk_ one>
RMP_MAX_CHARS=13000
```

Two things to know, both found by testing against the endpoint:

- Groq does not serve Llama 3.3 any more. `openai/gpt-oss-120b` is the best of
  the eleven models it does serve. `cli check` lists them if that changes again.
- Groq's free tier allows **8,000 tokens per minute**, and a whole paper is
  about 12,700 — so `RMP_MAX_CHARS=13000` is not optional there. Sections get
  truncated rather than dropped, and the method and experiment sections are
  kept longest.

Then confirm:

```bash
.venv/bin/python -m runmypaper.cli check
```

It should end with `provider is working.` **Don't plan the demo around a live
extraction anyway** — use the cached ResNet run as the main thread and treat a
live one as a bonus.

## The five-minute version

### 1. The problem (10 seconds, no clicking)

A paper describes a model in prose. Reproducing it means a person reading the
paper and writing the code. This takes a paper and produces a project that
runs — and proves it runs before handing it over.

### 2. Show the pipeline strip

Point at the eight stages across the top: `ingest → extract → scaffold →
generate → import → forward → step → train`.

The one thing worth saying: **code is never generated from the paper.** The
paper becomes a typed specification first, and the code is generated from the
specification. That split is what makes extraction and generation separately
measurable.

### 3. Press **Run pipeline** (resnet is already filled in)

It replays from cache, so it finishes in seconds. Watch the stages light up.

### 4. Specification tab — this is the part to dwell on

Every field sits next to **the verbatim quote from the paper it came from**, and
the model's confidence in it. Scroll to *What the paper never says*: ResNet never
states its epoch count, so `training.epochs` is listed as unresolved and the
default that was applied is recorded next to it.

> "A number the paper never printed is an assumption, not a result. The system
> says which is which, and the generated project's README repeats it."

### 5. Architecture tab

The forward graph, with each repeated block expanded in place. This is the
structured specification, not prose.

### 6. model.py tab

The only generated file. Everything else — the data loader, the training loop,
the smoke tests — is fixed scaffold driven by `config.yaml`. Keeping the
generated surface to one file is why generation is reliable enough to verify.

### 7. Gates tab

Four staged checks: does it import, does a forward pass produce the right shape,
does one training step produce gradients, does it train. They run in order and
stop at the first failure, and the failing gate's error is fed back to the model
to rewrite `model.py`.

> "The system doesn't claim the code is correct. It demonstrates that it runs."

### 7b. Optional, and the most sophisticated thing you can say

In the **Open a finished run** dropdown there is a second run, `wideresnet`,
showing **4/4 gates**. Do not present it as a success. Present it as this:

Its specification is nearly empty — `architecture.graph` has **zero layers**,
and thirteen fields are listed as unresolved, because Groq's free tier forced
the paper down to 8,000 characters and the extractor never saw the architecture
tables. The compiler refused it, correctly. The fallback then asked the model to
write `model.py` anyway, and the model produced a real WRN-28-10 with
**36,479,194 parameters against the paper's reported 36.5M** — from the title
and almost nothing else.

Two things follow, and they are the point:

1. **Passing the gates does not mean the specification was right.** The gates
   prove the code runs. They cannot prove it is the paper's architecture.
2. **On a famous paper, a language model can reproduce the architecture from
   memory without reading the paper at all.** So the `no_ir` baseline will look
   deceptively strong on ResNet or VGG, and a benchmark built only from famous
   papers would measure recall of the training data rather than reading
   comprehension.

That is exactly why the benchmark scores the extracted spec against a
hand-labelled gold spec, and splits errors into *wrong*, *missed* and
*hallucinated*, instead of just reporting how often the code ran.

If you are asked what you would do about it: hold out papers the model is
unlikely to have memorised, and compare `no_ir` against `compiled` on those.

### 8. Schema guard tab — the strongest slide

Two specs are listed:

- `spec.before-fix.json` — **rejected, 3 problems.** This is real: the first
  extraction this project ever ran produced three stages of 64 channels and then
  a `Linear(512, 1000)`. Those cannot connect. It also named its data source
  "ILSVRC 2012", which the data loader does not understand, so it would have
  silently trained on random noise.
- `spec.json` — **valid.**

> "The schema catches a specification that contradicts itself before any code is
> generated, and the error it produces is specific enough that the model usually
> repairs it without a human involved."

This is the best thing to show, because it is a bug the system found in its own
output and now prevents.

## If you are asked

**"Which model does it use?"** Gemini 3.8 Flash on Google's free tier, through
an OpenAI-compatible endpoint. One file (`llm.py`) talks to the provider, so
Groq, OpenRouter or a local Ollama work with no code change. Running on a free,
smaller model is deliberate: it strengthens the claim that the specification
carries the accuracy rather than the model's raw strength.

**"Where are the residual connections?"** — ask this of yourself before someone
else does. The extraction recorded the block's layers but not the shortcut that
sums the block's input back in, so the compiled model is a plain 20-layer CNN
with ResNet-20's exact widths and parameter count, not a residual network. The
compiler already supports it: a block containing an `Add` layer compiles to a
shortcut, with a 1×1 projection when the body changes shape. What is missing is
one line in the extraction prompt asking for that `Add`. It was left out on
purpose today, because changing the prompt invalidates the cached extraction and
your demo would then need an API call it may not have. Say that plainly — it is
a known gap with a known fix, which is a much better answer than not having
noticed.

**"How do you know it's accurate?"** That's the measurement that isn't done yet.
`bench/papers.yaml` fixes 15 papers, chosen before any measurement so results
can't be cherry-picked. Each needs a hand-corrected gold specification. Three
arms — no specification, specification without repair, specification with
repair — so each component is credited separately. Extraction errors split into
*wrong*, *missed* and *hallucinated* rather than one accuracy number, because
hallucinated is the one that matters and the one an average hides.

**"What's left?"** The gold specifications are the bottleneck and the next piece
of work. Also: the gates run as local subprocesses with a timeout but no
container isolation, and sequence and segmentation tasks need their own data
loader, which blocks the transformer, ViT and U-Net entries.

**"Did you write the tests?"** 41 offline checks, no API key needed:
`.venv/bin/python tests/offline.py`. They cover ingest, the budget, the
scaffold, all four gates on both correct and deliberately broken code, the
metrics, and the schema guards.

## If something goes wrong

**The page won't load.** The port may be taken. Run it again — it takes the next
free port and prints the URL.

**A run hangs on `extract`.** It's waiting on the free-tier API, which returns
"high demand" often; the code backs off and retries. Don't wait on stage: use
**Open a finished run → resnet** instead, which reads from disk and needs no
network at all. Keep "Use cached model calls" ticked for the same reason.

**No network in the room.** Everything except a *fresh* extraction works
offline: open a finished run, the schema guard, and the whole test suite.

**Nothing works at all.** Fall back to the terminal:

```bash
.venv/bin/python tests/offline.py                      # 41 checks pass
cat out/resnet/spec.json                               # the specification
.venv/bin/python -c "
from runmypaper.spec import PaperSpec
from pydantic import ValidationError
try: PaperSpec.model_validate_json(open('out/resnet/spec.before-fix.json').read())
except ValidationError as e:
    [print('.'.join(map(str, x['loc'])), '->', x['msg']) for x in e.errors()]"
```

That last one prints the three defects the schema catches, which is the same
point as the Schema guard tab.
